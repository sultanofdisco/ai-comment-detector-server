# AI Comment Detector 로컬 실행 가이드

이 문서는 아래 두 폴더를 함께 실행해 X(트위터) 댓글 AI 탐지 기능을 사용하는 방법을 정리합니다.

| 폴더 | 역할 |
|------|------|
| `ai-comment-detector-server` | FastAPI 분석 서버 (모델 추론 API) |
| `ai-comment-detector-extension` | Chrome 확장 프로그램 (댓글 수집 + UI 표시) |

**중요:** 확장 프로그램은 단독으로 동작하지 않습니다. 반드시 **서버를 먼저 실행**한 뒤 확장 프로그램을 로드해야 합니다.

---

## 1. 전체 동작 흐름

```text
X 댓글 페이지
    ↓ (content script가 댓글 추출)
Chrome 확장 프로그램 (background service worker)
    ↓ (HTTP 요청)
로컬 서버 http://127.0.0.1:8000
    ↓ (2단계 모델 추론)
댓글 옆 배지 / XAI 툴팁 / 계정 분석 패널 표시
```

---

## 2. 준비물

### 공통

- Google Chrome
- 두 프로젝트 폴더가 로컬에 있어야 함

### 서버 (`ai-comment-detector-server`)

- Python 3.10 이상 권장 (3.9도 가능하나 추가 패키지 필요, 아래 참고)
- 가상환경(`.venv`) 권장
- 학습된 모델 파일 (`saved_models/`)

### 확장 프로그램 (`ai-comment-detector-extension`)

- 별도 빌드 없음 (소스 폴더를 Chrome에 직접 로드)
- 서버 주소: `http://127.0.0.1:8000` (코드에 고정)

---

## 3. 폴더 경로 예시

본인 환경에 맞게 경로만 바꿔서 사용하세요.

```text
/Users/dyne/ai-comment-detector-server
/Users/dyne/ai-comment-detector-extension
```

## 4. 서버 실행 (1단계)

### 4-1. 가상환경 생성 및 의존성 설치

**macOS / Linux**

```bash
cd /Users/dyne/ai-comment-detector-server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Windows (PowerShell)**

```powershell
cd C:\Users\user\ai-comment-detector-server
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

#### Python 3.9 사용 시 추가 설치

Python 3.9에서 서버가 `str | None` 타입 오류로 시작되지 않으면 아래를 설치합니다.

```bash
pip install eval_type_backport
```

### 4-2. 모델 파일 확인

서버는 `saved_models/` 아래 모델을 로드합니다.

**Stage 1 (필수)** — `saved_models/stage1_kcbert_binary/`

- `artifacts.json`
- `bert_classifier/`

**Stage 2 (선택)** — `saved_models/stage2_llm_hybrid/`

- `artifacts.json`
- `xgb_model.joblib`
- `bert_classifier/`

Stage 2가 없어도 Stage 1(`human` / `ai`) 판별은 동작합니다.  
`ai_score`가 threshold(기본 0.85) 이상일 때만 Stage 2 LLM 분류(`gpt`, `claude`, `gemini`, `deepseek`)가 시도됩니다.

모델이 없으면 `/health` 또는 `/predict`에서 `503` 오류가 날 수 있습니다.

### 4-3. 서버 시작

프로젝트 루트(`ai-comment-detector-server`)에서 실행합니다.

```bash
python -m uvicorn server.app:app --reload --host 127.0.0.1 --port 8000
```

> `--host 127.0.0.1`을 권장합니다. 확장 프로그램이 이 주소로 요청합니다.

### 4-4. 서버 정상 여부 확인

브라우저 또는 터미널에서 확인합니다.

```bash
curl http://127.0.0.1:8000/health
```

정상 응답 예시:

```json
{
  "status": "ok",
  "stage1_model_dir": ".../saved_models/stage1_kcbert_binary",
  "stage2_model_dir": ".../saved_models/stage2_llm_hybrid",
  "device": "cpu",
  "ai_threshold": 0.85,
  "llm_threshold": 0.92
}
```

API 문서: http://127.0.0.1:8000/docs

### 4-5. 서버 종료

서버를 실행한 터미널에서 `Ctrl + C`를 누릅니다.

---

## 5. 확장 프로그램 로드 (2단계)

서버가 켜진 상태에서 진행합니다.

### 5-1. Chrome 확장 프로그램 페이지 열기

주소창에 입력:

```text
chrome://extensions
```

### 5-2. 개발자 모드 활성화

오른쪽 상단 **개발자 모드**를 켭니다.

### 5-3. 확장 프로그램 폴더 로드

1. **압축해제된 확장 프로그램을 로드합니다** 클릭
2. `ai-comment-detector-extension` 폴더 선택

예:

```text
/Users/dyne/ai-comment-detector-extension
```

### 5-4. 로드 후 확인

- 목록에 **X-AI 댓글 탐지기**가 표시되는지 확인
- 오류 배너가 없는지 확인
- 코드를 수정했다면 확장 프로그램 카드의 **새로고침** 버튼 클릭

### 5-5. 서버 연결 확인 (선택)

1. `chrome://extensions`에서 해당 확장의 **서비스 워커** 클릭
2. 콘솔에 `[AI Detector] server status: ok` 로그가 보이면 연결 성공

서버가 꺼져 있으면 `[AI Detector] server is unreachable: TypeError: Failed to fetch` 가 표시됩니다.

## 6. 실제 사용 (3단계)

### 6-1. X 댓글 페이지 접속

아래 도메인의 **게시물(트윗) 상세 페이지**로 이동합니다.

- `https://x.com/.../status/...`
- `https://twitter.com/.../status/...`

댓글이 달린 트윗 상세 페이지에서 자동 분석이 시작됩니다.

### 6-2. 화면에서 확인할 수 있는 것

| 기능 | 설명 |
|------|------|
| AI 배지 | AI로 분류된 댓글 옆에 라벨·점수 표시 |
| XAI 툴팁 | AI 의심 사유 텍스트 |
| 배지 클릭 | False Positive 후보를 서버 CSV로 저장 |
| Account 버튼 | 해당 계정 replies 페이지 분석 뷰 열기 |
| Side Panel | 저장된 분석 결과 상세 보기 |

`human`으로 분류된 댓글은 배지가 표시되지 않습니다.

### 6-3. Side Panel 열기

Chrome 툴바의 확장 프로그램 아이콘을 클릭하거나, side panel을 열어 분석 결과를 확인합니다.

## 7. 제공 API 요약 (서버)

| 메서드 | 경로 | 용도 |
|--------|------|------|
| `GET` | `/health` | 서버·모델 상태 확인 |
| `POST` | `/predict` | 댓글 AI 판별 |
| `POST` | `/feedback/false-positive` | 오탐 데이터 CSV 저장 |
| `GET` | `/admin/model-usage` | 예측 로그 기반 사용 통계 |

확장 프로그램은 주로 `/health`, `/predict`, `/feedback/false-positive`를 사용합니다.

---

## 8. 환경 변수 (선택)

서버 실행 전에 필요 시 설정합니다.

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `STAGE1_MODEL_DIR` | `saved_models/stage1_kcbert_binary` | 1단계 모델 경로 |
| `STAGE2_MODEL_DIR` | `saved_models/stage2_llm_hybrid` | 2단계 모델 경로 |
| `AI_THRESHOLD` | `0.85` | 2단계 실행 임계값 |
| `MODEL_DEVICE` | `cpu` (CUDA 없을 때) | 추론 디바이스 |
| `CORS_ORIGINS` | `*` | CORS 허용 origin |

예시:

```bash
export MODEL_DEVICE=cpu
python -m uvicorn server.app:app --reload --host 127.0.0.1 --port 8000
```

## 9. 서버 주소 변경 시

확장 프로그램의 서버 URL은 아래 파일에 고정되어 있습니다.

- `ai-comment-detector-extension/background/service-worker.js`
- `SERVER_BASE_URL` 상수

`manifest.json`의 `host_permissions`에도 동일한 origin이 있어야 합니다.

```json
"host_permissions": [
  "https://x.com/*",
  "https://twitter.com/*",
  "http://127.0.0.1:8000/*"
]
```

주소를 바꾼 뒤에는 확장 프로그램을 **새로고침**해야 합니다.

## 10. 문제 해결

### `[AI Detector] server is unreachable: TypeError: Failed to fetch`

1. 서버가 실행 중인지 확인
2. `http://127.0.0.1:8000/health` 가 브라우저에서 열리는지 확인
3. `--host 127.0.0.1` 로 실행했는지 확인 (다른 호스트/포트 사용 시 확장 코드도 수정)
4. 확장 프로그램을 새로고침한 뒤 X 페이지도 새로고침

### 배지가 안 뜰 때

1. **트윗 상세 페이지**(`/status/...`)인지 확인 (일반 타임라인이 아닌 댓글 페이지)
2. 서버 `/predict` 요청이 들어오는지 터미널 로그 확인
3. `human` 댓글만 있으면 배지가 없을 수 있음
4. content script 콘솔에 `[AI Detector] status-page analyzer loaded` 로그 확인

### 모델 관련 503 오류

- `saved_models/stage1_kcbert_binary` 파일이 있는지 확인
- `/health` 응답의 `stage1_model_dir` 경로 확인

### 예전 결과가 계속 보일 때

확장 프로그램은 `chrome.storage.local`에 결과를 캐시합니다.

1. `chrome://extensions`에서 확장 프로그램 새로고침
2. X 페이지 새로고침
3. 필요 시 확장 storage 초기화

### Python import / 타입 오류

- Python 3.10+ 사용 권장
- 3.9 사용 시: `pip install eval_type_backport`
